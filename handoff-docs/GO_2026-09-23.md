# Go package — "Where should I ride this Saturday?" (2026-09-23)

The one product from the 2026-09-18 strategy: pass + city → the three best
mountains for this Saturday, with the surface, the drive, honest
confidence, a share card and a Thursday email. No login for the page.

## What shipped

| Piece | Where |
| --- | --- |
| Ranking (pure) | `lib/saturday/rank.ts` — `rankForSaturday()`, `WEIGHTS` table, `confidenceFor()`, `accessFor()` |
| Date helpers | `lib/saturday/dates.ts` — "this Saturday" in the city clock, DST-safe |
| Cities | `lib/origins.ts` `LAUNCH_CITIES` (+ Washington DC, Chicago, Minneapolis, Detroit) and `lib/saturday/cities.ts` |
| URL state | `lib/saturday/url.ts` — `?city=&pass=&product=&max=&day=` (+ `lat`/`lng` for `city=geo`) |
| Loader | `lib/saturday/load.ts` — shared by the page (anon key, cached 10 min per origin + radius) and the cron (service key) |
| Page | `app/go/page.tsx` + `GoForm` / `PickCards` / `ShareButton` / `ThursdayOptIn` |
| Share card | `app/go/og/route.tsx` (route handler: the file-convention `opengraph-image` cannot read the query string) |
| Opt-in API | `app/api/go/subscribe/route.ts` — saves `profiles.preferred_origin` + `profiles.pass_product`, enables `digest_subscriptions` |

pill is left to the integrator (map package owns that file).

## Rules the ranking follows

* A resort is a pick only when `deriveResortStatus` says it is running
  (verified open, limited, or likely open from declared season dates), or
  when the target Saturday is its announced (not projected) opening day.
  Closed / off-season / "check resort" rows go to the excluded list with
  the reason. Before the season the page shows the opening countdown.
* Pass: family from `resorts.passes[]`, product rules from
  `lib/passAccess`. A full blackout on the target date excludes the resort
  and says so; a day-access blackout is printed; an unpublished list is
  printed as unknown, never as open; "not included" products exclude.
* Surface: `lib/snowSurface` dormancy gate, then the classifier rolled
  forward one forecast day at a time to the target; confidence capped by
  horizon (0-1 days as-is, 2 days high→medium, 3+ low). Today uses the
  cron's stored class when it is < 36 h old.
* Score weights are in one table (`WEIGHTS`) and printed on the page under
  "Why these three".
* Confidence tag = horizon + data age only (`confidenceFor`), never how
  good the pick looks.
* Drive: `drive_time_cache` for origins with `driveCache: true`, else the
  straight-line estimate labelled "≈" (Philadelphia had no cache rows on
  2026-09-23 and falls back automatically).

## Founder tasks

1. Run `handoff-docs/sql/2026-09-23-go.sql` in the Supabase SQL editor
   (idempotent). Until then: the page works, the opt-in saves the city and
   says the email is coming, the cron exits with a reason.
2. Optional: run the drive-time cache job for the four new cities with
   `origin_name` exactly "Washington DC", "Chicago", "Minneapolis",
   "Detroit", then set `driveCache: true` on those entries in
   `lib/origins.ts`.
3. Test the email once: `node scripts/pipeline-trigger.mjs thursday-picks --force`
   (needs `CRON_SECRET`, `RESEND_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY` and at
   least one opted-in profile).
