# Go package — "Where should I ride this Saturday?" (2026-09-23)

The one product from the 2026-09-18 strategy: pass + city → the three best
mountains for this Saturday, with the surface, the drive, honest
confidence, a share card and a Thursday email. No login for the page.

## What shipped

| Piece | Where |
| --- | --- |
| Ranking (pure) | `lib/saturday/rank.ts` — `rankForSaturday()`, `WEIGHTS` table, `confidenceFor()`, `accessFor()` |
| Date helpers | `lib/saturday/dates.ts` — "this Saturday" in the city clock, DST-safe |
| Cities | `lib/origins.ts` `LAUNCH_CITIES` (+ Washington DC, Chicago, Minneapolis, Detroit) and `lib/saturday/cities.ts` |
| URL state | `lib/saturday/url.ts` — `?city=&pass=&product=&max=&day=` (+ `lat`/`lng` for `city=geo`) |
| Loader | `lib/saturday/load.ts` (reads, chunked, cap 400 with honest `rankedIds`) + `lib/saturday/cached.ts` (10 min per origin + radius, shared by the page and the share card); the cron calls the loader directly with the service key |
| Page | `app/go/page.tsx` + `GoForm` / `PickCards` / `ShareButton` / `ThursdayOptIn` |
| Share card | `app/go/og/route.tsx` (route handler: the file-convention `opengraph-image` cannot read the query string) |
| Opt-in API | `app/api/go/subscribe/route.ts` — saves `profiles.preferred_origin` + `profiles.pass_product` (the Thursday consent); creates a `digest_subscriptions` row with `enabled = false` if none, never touches the weekly digest flag. DELETE clears `pass_product` |
| Unsubscribe | `app/api/digest/unsubscribe` with `&list=thursday` (lib/digestUnsubscribe.ts) clears `pass_product` only; the plain link still stops the weekly digest only |
| Thursday email | `app/api/cron/thursday-picks/route.ts` + `lib/email/templates/thursdayPicks.ts` |
| SQL | `handoff-docs/sql/2026-09-23-go.sql` — `profiles.pass_product`, `saturday_predictions` |
| Cron | `vercel.json` `30 13 * * *` daily; the route exits unless Thursday in America/New_York, or `?force=1` with the secret |

Entry points: footer link (every page), `/get`, `/account`. The map header
pill is left to the integrator (map package owns that file).

## Rules the ranking follows

* A resort is a pick only when `deriveResortStatus` says it is running
  (verified open, limited, or likely open from declared season dates), or
  when the operator's explicit opening date falls on or before the target
  (an opening the Friday before is worded "opens Jan 15", not "opening
  day"). A projected date ("(projected)") or an approximate phrase
  ("Late November") never promotes a resort: it stays in the countdown
  and the excluded list says "not confirmed" / "exact date not
  announced". Closed / off-season / "check resort" rows go to the
  excluded list with the reason. Before the season the page shows the
  opening countdown; after it (nearest announced opening > 120 days out,
  or closed-for-season rows dominate) the heading says the season is over.
* Pass: family from `resorts.passes[]`, product rules from
  `lib/passAccess`. With a product: a full blackout on the target date
  excludes the resort and says so; a day-access blackout is printed; an
  unpublished list is printed as unknown, never as open; "not included"
  products exclude. With a family only: every product of the family is
  checked, the resort is excluded only when all are blacked out, and
  otherwise the line names which products are ("Jan 16 blackout depends
  on product: Ikon Base, Session blacked out, Ikon open"). The countdown
  prints the day allowance without a blackout verdict.
* Every forecast number is labelled with the source on the forecast row
  (`days[].source`: NWS / Open-Meteo / NWS + Open-Meteo; v1 rows are NWS).
* When the loader's candidate cap (400) ever applies, resorts within
  reach but not fetched are excluded as "Beyond the N closest mountains
  ranked", never as "no weather on file".
* Surface: `lib/snowSurface` dormancy gate, then the classifier rolled
  forward one forecast day at a time to the target; confidence capped by
  horizon (0-1 days as-is, 2 days high→medium, 3+ low). Today uses the
  cron's stored class when it is < 36 h old.
* Score weights are in one table (`WEIGHTS`) and printed on the page under
  "Why these three".
* Confidence tag = horizon + data age only (`confidenceFor`), never how
  good the pick looks.
* Drive: `drive_time_cache` for origins with `driveCache: true`, else the
  straight-line estimate labelled "≈" (Philadelphia had no cache rows on
  2026-09-23 and falls back automatically).
