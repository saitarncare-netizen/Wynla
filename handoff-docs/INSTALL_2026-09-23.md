## Nudge rules (global `InstallPrompt`)

- Counts one visit per browser session (`sessionStorage`), stores the total in `localStorage` (`wynla_install_visits`).
- Shows the bottom pill on the 2nd visit or later, 8 s after load, at most once per 7 days (`wynla_install_nudge_at`).
- Never on `/login`, `/auth/*`, `/trip/*` (shared trip links), `/lists/*`, `/get`, `/offline.html`, inside the installed app, nor in browsers that cannot install (desktop Firefox, Safari before 17, and Safari 17+ on macOS where Add to Dock is left to /get and /account).
- Position: `bottom: calc(env(safe-area-inset-bottom) + 16px)`; on the map `+ 72px` so it clears the feedback / compare / location pills. **Map package note:** the nudge occupies the band 72–140 px above the home indicator on `/`, full width up to 480 px, `z-index` 70.
- Dismiss hides it for the current load; the 7-day timer is what stops it coming back.

## How to test

### Android Chrome (mode A)
1. Open https://wynla.app in Chrome, visit twice (close the tab in between) or go to `/get`.
2. Tap **Install Wynla**. Chrome shows the richer install sheet with the three screenshots and the description. Tap **Install**.
3. Expect the "Installed. Open Wynla from your home screen." toast, a WebAPK icon in the app drawer, and the button gone from `/get` and `/account`.
4. `chrome://inspect` → Application → Manifest shows no installability warnings; Service Workers shows `sw.js` with the current `VERSION` caches.
5. Airplane mode → open the app → the branded offline page shows (navy, Wynla mark, **Try again**); tapping Try again reloads the page you asked for; turning the network back on reloads automatically after about a second.
6. Samsung Internet 27+ never fires `beforeinstallprompt`: the same button opens the generic menu guide, which is correct.

### iPhone Safari (mode B)
1. Open https://wynla.app in Safari; go to `/get` or wait for the nudge.
2. Tap **Add to home screen** → sheet says: Share (bottom bar; on iOS 26 behind the three dots) → Add to Home Screen → Add, and warns that the installed app needs its own sign-in.
3. Follow the steps; the launch image is navy with the mark; the status bar overlays the navy header on the map, and every other page starts below the clock (check `/trips`, `/favorites`, `/account`, `/login`, `/compare`, `/resort/vail`).
4. Chrome / Firefox / Edge on iOS get their own share-button location in step 1.
5. Sign in inside the installed app once. Magic links from Mail still open in Safari, not the app — that fix (email code login) belongs to the auth package.

### TikTok / Instagram in-app browser (mode C)
1. Put `https://wynla.app/get` in the TikTok bio, open it from the TikTok app.
2. The card reads "You're inside TikTok"; tap **Open outside TikTok** → **Open in Safari** (iOS, `x-safari-https://`) or **Open in Chrome** (Android, `intent://`).
3. The page reopens in the real browser at `/get?from=tiktok` and, on iOS, the guided sheet opens by itself.
4. If the deep link is blocked (Instagram on iOS is the usual offender), **Copy link** and the "menu → Open in browser" hint are the fallbacks.

### Desktop Chrome / Edge
`/get` → **Install Wynla** → native dialog → app window. Firefox and Safari 16 on Mac see "Install isn't available in this browser" with no button; Safari 17+ on Mac gets **Add to Dock** with the File > Add to Dock steps.

### Service-worker update
Deploy a new build with a bumped `VERSION`: an open tab reloads once when the new worker activates; no reload loop (the reload is gated on a controller having existed).

### Local testing
The worker is unregistered in `next dev`. To test install / offline locally run `npm run build && npm run start` and open http://localhost:3000 in Chrome — Chrome treats localhost as a secure context, so the install prompt and the worker both work there.

### Push re-sync (after the SQL is applied)
Sign in, enable a snow alert on any resort, then hard-reload once: Network tab shows one `POST /api/push/subscribe` returning 200 and `push_subscriptions.last_seen_at` for that endpoint moves to now. Signed out, no POST is made.

## Play Store (TWA) path — later

Prerequisites are now met: manifest with `id`/`scope`/screenshots, maskable icon, and a real fetch handler with offline fallback (Play policy 4.3 rejects "thin wrappers" without one).

1. Google Play developer account ($25 once). Personal accounts created after 2023-11-13 must run a closed test with 12 testers for 14 days before production.
2. `npx @bubblewrap/cli init --manifest https://wynla.app/manifest.json`, then `npx @bubblewrap/cli build` (or PWABuilder → Android package). Package name suggestion: `app.wynla.twa`.
3. Publish `/.well-known/assetlinks.json` with the signing certificate's SHA-256 (Bubblewrap prints it). Without it the TWA shows a browser toolbar.
4. Keep the listing screenshots in sync with `/screenshots/*.png` (or capture real UI once the map redesign is final).
5. iOS App Store wrapper stays deferred (Guideline 4.2 risk, needs Mac + Xcode + $99/yr); revisit post-OPT per the mobile strategy.
