## Snap points (`ResortSheetMath.snapHeights`)

| Snap | Height | Shows |
|---|---|---|
| peek | 140 px | Hero strip: name, state · region, status pill, drive from origin, one key stat (new snow > % open > vertical > trails). Map fully pannable. |
| half | 52 % of `innerHeight` (min peek + 120, max full − 80) | Hero + 4-tile stat row + drive source line + pass chips; action bar docked at the bottom of the visible sheet. |
| full | 92 % of `innerHeight` | Hero collapses to a 56 px title bar (photo fades, name shrinks, × stays), body scrolls (pass rules, countdown, nearby picks), map sliver stays visible at the top. |

Gestures: drag on the handle or the hero anywhere; flick (≥ 0.45 px/ms)
moves one snap in the flick direction, a downward flick from peek closes;
slow release snaps to the nearest; releasing under 70 px closes. Body:
below full any vertical move drags the sheet (drag up expands before
content scrolls); at full an upward move scrolls the content and a
downward move drags the sheet only when the content is at the top.
Sideways swipes go to the horizontal strips inside. Keyboard: the handle
is a button, arrow up / down resize, Escape closes (MapPage). Fresh open
lands on half; pin → pin taps keep the current snap; a tap on bare map
collapses to peek; the phone back gesture closes (one history entry per
open sheet, replaced in place when the resort changes, popped by the ×).
Back from `/resort/[slug]` restores the sheet from `history.state.wnSheet`.

Reduced motion: no slide-in animation, no height / hero transition, map
padding jumps instead of easing.

## Map padding

`ResortPanel` forwards only settled heights; `MapPage` converts them with
`sheetMapPadding` (peek → 140, half → 52 %, full → holds the half value
because the sheet covers the map anyway) and passes `resortSheetPadding`
to `MapView`, which eases the camera padding so the selected pin stays in
the visible sliver. Desktop keeps the 380 px right padding.

## Bottom stack (`--wn-bottom-stack`)

Defined on the map root (`[data-route="map"]`), in px from the container's
bottom edge (the container already excludes the phone tab bar via
`--wn-tab-bar-h` in `app/globals.css`):

- 40 px: the Mapbox attribution + wordmark band (terms requirement)
- 148 px: while the install nudge (`[role=region][aria-label="Install Wynla"]`) is in the DOM
- peek sheet height + 12 px: while a resort sheet is at peek

`data-sheet-snap="peek|half|full"` is set on the same root while a phone
sheet is open. Consumers: `bottom: var(--wn-bottom-stack, 40px)` and hide
under `[data-sheet-snap=half]` / `[data-sheet-snap=full]` (Tailwind:
`[[data-sheet-snap=half]_&]:hidden [[data-sheet-snap=full]_&]:hidden`).
List (centre), Location (right) and Compare (centre, +56 px) already do.
**FeedbackButton (a11y package) should switch from `bottom-10` to the
variable and the two hidden variants; until then it stays at 40 px and is
covered by a peek sheet.**

## Chrome budget (375 x 812, `ResortSheetMath.MOBILE_CHROME`)

| Row | Height |
|---|---|
| Gap under the status bar | 8 |
| Primary row | 44 |
| Pass chips | 40 |
| Secondary row (only with content; on phones the Saturday pill is always content) | 44 |
| Founder banner (May–Oct, until dismissed) | 32 |
| **Total** | **168 px** (92 px with only the two mandatory rows) |

Measured from the row heights, which are fixed with `h-11` / `h-10` /
`h-8` rather than padded content; `tests/resortSheetMath.test.ts`
asserts the sum stays under 170. At runtime the same number is published
as `--wn-header-h` on the map root (ResizeObserver), read it in DevTools
with `getComputedStyle(document.querySelector('[data-route=map]')).getPropertyValue('--wn-header-h')`
(add `env(safe-area-inset-top)` on a notched phone: the budget excludes
the status bar, which the map shows through).

## Why not vaul

Evaluated against audit benchmark #1. It does not expose the in-flight
drag height (the map padding must follow the settled snap and the pill
stack the peek height), its non-modal mode still installs body scroll
locks that fight Mapbox, and it adds `@radix-ui/react-dialog` to the map
bundle. The gesture model here is ~150 lines with every branch in pure,
tested helpers.

## How to test on iPhone

1. Open https://wynla.app (or the preview) in Safari and in the installed app.
2. Tap a pin: the sheet opens at half with the photo hero, 4 tiles (each with Measured / Reported / Forecast and an age), and the gold Plan trip bar at the bottom. The map eases so the pin sits above the sheet.
3. Drag the hero up: it reaches full, the photo fades to a white 56 px title bar, a map sliver stays visible, and only now does the body scroll. Scroll down, then scroll back to the top and keep pulling: the sheet collapses.
4. Flick down from half: peek (name, status, drive, one stat). Flick down again: closes. Tap a pin while at peek: the sheet stays at peek with the new resort.
5. Tap bare map with the sheet at half: it collapses to peek. Swipe back from the screen edge with the sheet open: it closes and you are still on the map.
6. Tap "Full resort page →", then swipe back: the same sheet is open again.
7. Header: one button row (Search / Plan / Filters / Account, 44 px squares with labels), one chip row, one shortcut row, the founder strip; nothing wraps at 375 px. Chips scroll with no scrollbar.
8. Bottom: the List pill opens the resort list; Location sits bottom-right; with the install nudge showing both move above it; with a sheet at peek they sit on its shoulder; at half / full they hide.
9. Settings → Accessibility → Motion → Reduce Motion: the sheet appears and resizes without animation.
10. VoiceOver: the handle reads "Resize resort sheet (half). Arrow keys resize, Escape closes."; every button in the header and action bar has a name.

## Known limits / follow-ups

- A filter tap while the sheet is open rewrites the history entry's URL; the back gesture then returns to the pre-filter URL (same as any back press on this page). The sheet key is re-asserted on every query change so back still closes the sheet.
- `snow_new_24h_in` written by the daily NOHRSC / SNOTEL analysis has no stamp of its own; the tile dates it by the weather sync (`weather_cache.fetched_at`, "Measured · 3h ago") or says "Measured · daily" when the payload lacks it.
- Reopen-from-history also fires after a hard reload of the map with a sheet entry on top (state survives reloads), which matches Google Maps.
- FeedbackButton still uses `bottom-10` (a11y package owns it): see the bottom-stack note above.
